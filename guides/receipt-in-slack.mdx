Receipt's Slack app is a direct Slack OAuth integration, not one of the Receipt Connect data connectors covered on [Receipt Connect and the connector catalog](/platform/integrations). Installing it authorizes a bot user in your Slack workspace; it doesn't hand Receipt a data connection to manage separately.

## Installing Slack

The sidebar's **Slack** item opens `/api/slack/install` in a new tab. You need to be signed in to Receipt with an active organization, and you need to be an organization admin:

- Not signed in, or no active organization: `Sign in and select a workspace before installing Slack.`
- Signed in but not an admin: `Only workspace admins can install Slack.`

From there Receipt redirects you into Slack's own OAuth authorization screen. The link Receipt builds for that redirect is only valid for **ten minutes**; if you sit on it too long, or reuse an old one, Slack sends you back to a page that reads:

> `Slack installation state is invalid or expired. Start again from Receipt.`

There's no way to extend that window — start over from the sidebar link.

Once the authorization completes, Receipt shows:

> `@receipt added to <team name>!`
> `Go to any channel, type /invite @receipt, then mention @receipt to get started.`

<Note>
A Slack workspace belongs to exactly one Receipt organization. You can't split one Slack team across two organizations, and reinstalling doesn't move it.
</Note>

## What the app can and can't do in Slack

Receipt's Slack app requests exactly six scopes: `app_mentions:read`, `channels:history`, `chat:write`, `reactions:write`, `users:read`, and `users:read.email`. It requests no user tokens, no `commands` scope, and no direct-message scope — so it cannot see or use Slack slash commands, and it cannot message you directly.

Consistent with that scope list, none of the following are implemented: slash commands, interactive buttons or modals, direct messages, an App Home tab, file uploads, or message shortcuts. The entire surface is: get mentioned in a channel, and reply in that channel's thread.

## Getting a response

When you `@mention` Receipt in a channel — or reply without tagging it inside a thread it's already active in — Receipt adds an :eyes: reaction to your message, then posts:

> `:hourglass_flowing_sand: <@user> *Working on it…*`
> `_I’ll post the result in this thread._`

Everything that happens next edits that same message rather than posting new ones, so the thread doesn't fill up with status noise.

While the work runs, Receipt posts an update only when the run moves to a new phase, and those updates are throttled to roughly one every 20 seconds with a cap of 12 per run. Three phases produce a visible label — "Checking the connected data…", "Reviewing the results…", "Preparing the answer…" — and the phases in between, where the agent is actually running, deliberately produce no message at all, so you won't see a play-by-play of every internal step.

The terminal message carries a status label such as `Completed in 6s`, `Failed after 1m 05s`, `Canceled after …`, or `Blocked after …`, the answer itself with its markdown converted to Slack's formatting (tables become bulleted records, and long answers are truncated), and a **View Receipt** link back into the app. It never prints an internal run, job, or objective id — if you need one of those to investigate further, follow the link instead.

If a run is still going after Receipt's own ten-minute deadline, you'll see a message saying the objective is still working and taking longer than expected, with a link to check on it in Receipt — it deliberately never claims the run finished when it hasn't.

## Who Receipt runs as

Receipt resolves your Slack identity against your Receipt account before it runs anything for you:

- If your Slack account is already linked, the run happens as that Receipt user.
- If not, Receipt looks up your Slack email and matches it against your organization's members. A match links the two accounts automatically.
- If there's no match, Receipt replies with a signup link instead of running anything — you'll need to sign up with that email and mention Receipt again.
- If the organization has no seats left for a new member, Receipt refuses instead of creating one: `This workspace only has N seat(s) available. Remove pending invites or upgrade seats before inviting more members.`
