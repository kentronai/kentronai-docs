## Missing or too-thin topics (within the LLM-gateway scope)

1. **Tool policy as gateway policy.** `org_ai_policy` also carries `provider_native_tools_enabled`,
   `external_tools_enabled`, `disabled_tool_keys` and the API/mutators expose `toggle_provider_native_tools`,
   `toggle_external_tools`, `toggle_tool`; the wide event logs `allowedToolKeys`/`deniedToolKeys`. The report
   lists the columns but never describes how `ToolPolicyService` enforces them on a turn, which is part of the
   "policy-enforcing checkpoint" claim.
2. **Snapshot trust rule.** The 6.3 gap analysis omits that the short-circuit only applies when
   `provider_key_status.syncedAt > 0` (`model-policy.service.ts:256-259`); fresh orgs with the schema default
   behave differently from orgs that have saved/removed a key once.
3. **Slack and Teams surfaces.** Slack is mentioned only via the `slack_evt_` reservation and the runtime
   `/chat/route` call; Teams (`apps/teams`) is absent. Whether those surfaces pass through `resolveThreadModel`
   and the same deny lists is not established.
4. **Embeddings path.** `rag/attachment-content.pipeline.ts` is cited for key scope only; model
   (`text-embedding-3-small`), gating by `VITE_ENABLE_EMBEDDING`, and whether embedding calls produce usage rows
   are not covered.
5. **Runtime `/chat/route` endpoint.** Its authentication and what it returns are not described, although it is
   the one model-adjacent HTTP endpoint outside `apps/start`.
6. **Stream resume.** `StreamResumeService.layerDisabled` under `VITE_DISABLE_REDIS=true` is named in the env table
   only; the user-visible effect (no resume after reconnect) belongs beside the rate-limit caveat.
7. **Audit-trail adjacent routes.** `api/admin-metrics`, `api/receipt-trail/events`, `api/receipt-ingest/receipts`
   and `api/sessions/*` are listed but not characterised; they bear directly on the "unified audit trail" verdict.
8. **Where prompts live.** The report says prompts are stored "outside the chat thread itself" only in passing;
   message persistence (tables, retention, who can read) is not covered.
9. **Client-side visibility of policy.** `orgAiPolicy` is synced to browsers through Zero; which members can read
   the policy row (and therefore the `provider_key_status` snapshot) is not stated.
10. **Stale in-repo comments docs might copy.** Three found: `.env.example:121-122` (AI Gateway), `.env.example:130-132`
    (title model "follows the thread model"), and the guardrail service header (`guardrail-enforcement.service.ts:4-6`).
    The report flags the first; the other two are new.
11. **Test coverage map.** Beyond noting the Study Mode gap, the report does not say which gateway behaviours have
    tests (`model-gateway.service.test.ts`, `model-policy.service.test.ts`, `provider-key-store.test.ts`,
    `model-gateway-catalog.test.ts`), which matters for how confidently docs can state behaviour.
